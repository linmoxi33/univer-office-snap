# univer-office-snap

**A pure-stdlib, fully offline bridge between `.xlsx` files and Univer workbook snapshots — because Univer's own open-source repo explicitly does not ship file conversion.**

Why now: Univer is on GitHub Trending (1,828 stars this period) and its README tells you to *"use public Facade APIs"* while quietly moving XLSX import/export into a separately distributed, commercially licensed package. Anyone evaluating the open-source engine hits the same wall on day one: the demo renders beautifully, but there is no offline way to get a real spreadsheet in or out.

Upstream: https://github.com/dream-num/univer

## What upstream is, and what it lacks

[Univer](https://github.com/dream-num/univer) is an open-source, Apache-2.0 spreadsheet/document engine: it edits, calculates, renders, and persists workbooks as a JSON `Snapshot`.

It deliberately does **not** include Office file conversion in the open-source repository. From the `dev` branch README:

> "Snapshot persistence is separate from XLSX import and export, which uses the **separately distributed file-conversion capabilities**."
> — [README.md#L279](https://github.com/dream-num/univer/blob/dev/README.md#L279)

> "**Commercial extensions:** Commercial Web SDK plugins, Server SDK, and AI SDK capabilities beyond the open-source foundation are **distributed and licensed separately**."
> — [README.md#L618](https://github.com/dream-num/univer/blob/dev/README.md#L618)

This is not a one-off doc slip: the repo has an open, labeled export bug — range-reference formulas export in a form Office cannot recognize ([issue #3756](https://github.com/dream-num/univer/issues/3756), labels `scope:import export`, `scope:formula`). The conversion layer simply isn't in the OSS tree.

**One sentence:** It edits/calculates/renders spreadsheets and emits a Univer Snapshot, but nobody can convert XLSX ↔ Univer workbook snapshot offline from the open-source side — upstream routes that to separately distributed, separately licensed file-conversion capabilities (evidence: [README.md#L279](https://github.com/dream-num/univer/blob/dev/README.md#L279)).

## What this tool does — and does not do

**Does**

- `xlsx2snap` — parse an `.xlsx` (OOXML SpreadsheetML) into a Univer `IWorkbookData`-shaped snapshot: `sheetOrder` + `sheets[id].cellData[row][col]` with `{v:{strV|numV|boolV}, t, f}`.
- `snap2xlsx` — write a snapshot back to a valid `.xlsx`.
- `diff` — cell-level structural diff between two snapshots and/or `.xlsx` files (added/removed sheets, added/removed cells, changed cells, drift list).
- `roundtrip` — `xlsx → snapshot → xlsx` and then re-parse, proving the cell payload survived. Exit code reflects the result.
- Reads shared strings (`t="s"`), inline strings, `t="str"` cached results, numbers, booleans, error cells, multiple sheets, and formulas (`<f>` text is preserved verbatim).
- Every command emits machine-readable JSON with `--json`; exit codes are stable.

**Does not**

- Evaluate formulas (the formula text is carried through; no recalculation).
- Preserve styles, merges, column widths, number/date formats, rich text, conditional formatting, images, charts, pivots, comments, or frozen panes.
- Read legacy `.xls` (BIFF) or ODS.
- Talk to any network. There is no telemetry, no API key, no server.

## Install

Nothing to install. Requires Python 3.9+ (tested on 3.12) and only the standard library.

```bash
git clone <this-repo> && cd univer-office-snap
python3 --version   # 3.9+
```

## Usage

```bash
# 1. XLSX -> Univer snapshot (JSON on stdout)
python3 univer_office_snap.py xlsx2snap examples/in/sample.xlsx --json

# 2. XLSX -> snapshot written to a file
python3 univer_office_snap.py xlsx2snap examples/in/sample.xlsx --out examples/out/sample.snap.json

# 3. Snapshot -> XLSX
python3 univer_office_snap.py snap2xlsx examples/out/sample.snap.json --out /tmp/out.xlsx

# 4. Cell-level diff (exit 1 if anything drifted)
python3 univer_office_snap.py diff examples/in/sample.xlsx examples/in/sample.xlsx --json

# 5. Prove a round trip preserves every cell (exit 1 on drift)
python3 univer_office_snap.py roundtrip examples/in/sample.xlsx --json
```

Expected outputs live in [`examples/out/`](examples/out/): `sample.snap.json`, `roundtrip.json`, `diff-identical.json`. The committed `examples/in/sample.xlsx` is generated by `examples/make_sample.py`, which hand-writes the OOXML parts independently of the tool (so the fixture is not self-generated).

### `--json` shape

`xlsx2snap --json`:

```json
{
  "snapshot": {
    "id": "univer-workbook",
    "name": "Sales",
    "sheetOrder": ["sheet-01", "sheet-02"],
    "sheets": {
      "sheet-01": {
        "name": "Sales", "id": "sheet-01", "rowCount": 1000, "columnCount": 26,
        "cellData": {
          "1": {
            "1": {"v": {"numV": 10}, "t": 2, "s": "", "f": "", "si": "", "ref": "", "xf": ""}
          }
        }
      }
    }
  }
}
```

`roundtrip --json` / `diff --json` report `sheets_added`, `sheets_removed`, `cells_added`, `cells_removed`, `cells_changed`, `drift`, and `clean`.

### Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Pass — conversion succeeded / no drift detected |
| `1` | Drift or a detected problem (diff/roundtrip found a mismatch) |
| `2` | Usage or input error (missing file, bad JSON, not an XLSX) |

## Verification (real numbers, actually run)

- **20 unit tests, 20 passing** (`python3 -m unittest discover -s tests`), including 14 behavioral tests that drive the CLI and assert exit codes plus JSON fields.
- Compile check: `python3 -m py_compile univer_office_snap.py tests/test_univer_office_snap.py examples/make_sample.py` → clean.
- **Real upstream XLSX assets** (not fixtures) fetched from the Univer repo and converted offline:
  - `excel-base-sample.xlsx` → 1 sheet, **30 non-empty cells** (25 strings, 5 numbers); round trip: `clean=true`, 0 added / 0 removed / 0 changed.
  - `google-base-sample.xlsx` → 1 sheet (`工作表1`), **31 non-empty cells** (26 strings, 5 numbers); round trip: `clean=true`, 0 added / 0 removed / 0 changed.
- Offline check: commands run with the proxy pointed at `127.0.0.1:9` produce identical output; the tool imports nothing network-capable.

## Limitations

- Values/types/formulas only. This is a *data* bridge, not a layout-fidelity converter.
- Dates stay as Excel serial numbers (number type); no date formatting is applied.
- Worksheet ids are synthesized (`sheet-01`, `sheet-02`, …); the original sheet name is preserved in `name`.
- Output `.xlsx` uses inline strings. That is valid OOXML and opens in Excel/LibreOffice, but it is not a byte-for-byte clone of the input.
- Formula cells keep the formula text and cached value; they are not recalculated.

## 与同类项目的差异

Searched before building (`gh search repos "univer xlsx snapshot"`, `gh search repos "xlsx univer converter"`, `gh search code "IWorkbookData"`). No standalone, >500-star tool covers this; the only related code is inside application forks (e.g. `eternallycyf/ims-view-pc`, 26★, embeds an importer in its own app). This tool differs by being:

1. **Standalone and offline** — a CLI, not a component of a web app.
2. **Bidirectional and self-checking** — `diff` and `roundtrip` are first-class, so fidelity is asserted rather than assumed.
3. **Zero dependency** — stdlib only, no Univer runtime, no Node, no server SDK, no commercial license.
